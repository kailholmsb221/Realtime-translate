# ui — окно перевода, ассистент и история (Агент E)

Next.js 15 (App Router) + TypeScript strict + Tailwind v4. Состояние — только
React (`useState`/`useReducer`-логика в `src/lib/state.ts`), сторонних
стейт-менеджеров и UI-китов нет (CLAUDE.md, «Технический стандарт»).

Реализует ARCHITECTURE.md раздел 4.6:

- маленькое окно (~480×640, тёмная тема) с двумя лентами субтитров
  «Собеседник» (`stream: "in"`) и «Вы» (`stream: "out"`): оригинал + перевод;
- индикаторы задержки `stt/mt/tts/total` по каждому потоку, `total` подсвечивается
  красным при превышении бюджета 2500 мс (ARCHITECTURE.md раздел 2);
- кнопки Start/Stop, выбор `lang_in`/`lang_out` (ru/en/kk), `voice_id` и флаг записи
  с подписью «Запись включена — уведомите собеседника» (ARCHITECTURE.md раздел 8).
  В списке «мой голос» показываются только профили пользователя: автоклоны
  собеседника (имя с префиксом `auto_`, их заводит и удаляет сам движок —
  engine/orchestrator/autoclone.py) отфильтрованы. На странице истории такие
  профили скрывать незачем;
- панель ассистента: живой транскрипт последних 5 минут + кнопка «Подсказать ответ»
  (пока отключена, TODO — LLM-подсказки, этап 5);
- `/pipeline` — отладочная панель «whisper → NLLB → озвучка»: по каждой фразе видно
  промежуточные гипотезы и финал распознавания, текст, который движок передал в NLLB
  (`src_text`), перевод NLLB и задержки по стадиям; рядом — сырой лог событий.
  Подробнее — раздел «Панель пайплайна» ниже;
- `/history` — список сессий, `/history/[id]` — транскрипт с таймкодами, переводами
  и `<audio>`, если у сессии есть `audio_path`. Обе страницы — серверные
  компоненты: данные берутся из движка (`ENGINE_HTTP`) прямо при рендере, и
  транскрипт приезжает уже в HTML, а не догружается из браузера.

Вёрстка рассчитана на ширину от 360 px (окно можно сжимать).

## Запуск

```bash
cd ui
npm install          # если lock-файла нет и npm падает на peer-deps: npm install --legacy-peer-deps
npm run mock         # терминал 1: фейковый движок на ws://localhost:8765
npm run dev          # терминал 2: http://localhost:3000
```

Без движка и без мока UI тоже открывается: статус покажет «нет связи», Start будет
недоступен, история придёт из фикстур `mocks/data.json`.

| `npm run test:coverage` | отчёт покрытия по `src/lib` и `src/components` |

### Как UI работает с контрактами

`src/lib/contracts.ts` — зеркало `engine/contracts/*.json` на TypeScript:
`Envelope<T>`, `SttPartial`, `SttFinal`, `TranslationReady`, `TtsChunk`,
`SessionState`, `MetricsLatency`, `SessionStart`, `SessionStop`, `Lang`, `Stream`.
Схемы не копируются и не меняются — они неприкосновенны (CLAUDE.md, закон 2).
Расхождение ловит `tests/contracts.test.ts`: он читает JSON-схемы с диска и
сверяет набор `type`-констант и required-поля payload с ключами TS-типов.

`parseEnvelope(raw)` возвращает `Envelope | null`: проверяет `type` (известный),
`ts` (integer), `payload` (все поля на месте, лишних нет, enum-ы соблюдены).
Невалидные сообщения не роняют UI — они считаются в `invalidCount`.
`tts.chunk` разбирается, но редьюсером игнорируется (аудио играет движок).

Команды собираются хелперами `sessionStart(payload)` / `sessionStop()`;
хук отдаёт удобные `engine.start(payload)` и `engine.stop()`.

## Панель пайплайна (`/pipeline`)

Страница отвечает на вопрос «что именно распознал whisper, что из этого ушло в NLLB
и как он это перевёл». Открывается по ссылке «Пайплайн» в шапке окна перевода или
напрямую: <http://localhost:3000/pipeline>. Сессию можно запускать прямо отсюда —
это те же команды `session.start` / `session.stop`.

Одна карточка = одна фраза, новые сверху; четыре стадии:

| Стадия | Что показывает | Откуда данные |
|---|---|---|
| 1. Whisper · распознавание | цепочка гипотез `stt.partial` → финальная фраза, таймкоды фразы, `stt_ms` | `stt.partial`, `stt.final`, `metrics.latency` |
| 2. NLLB · вход | текст, который движок реально передал в перевод, и коды FLORES-200 (`eng_Latn → rus_Cyrl`) | `translation.ready.src_text` |
| 3. NLLB · перевод | что вернула модель, `mt_ms` | `translation.ready.text`, `metrics.latency` |
| 4. Озвучка и задержка | время до первого чанка TTS и общий `total_ms` (красный при превышении 2500 мс) | `metrics.latency` |

Стадия 2 отдельно подписывает, совпадает ли `src_text` с финалом whisper: если
между STT и MT текст изменится, карточка пометит это жёлтым — так видно, что
NLLB переводил не ту строку, которую показали субтитры.

Пока фраза не закрыта, сверху висит пунктирная карточка «whisper слушает» с текущей
гипотезой — в NLLB она ещё не ушла.

Слева от карточек — сырой лог событий (`{type, ts, payload}` как есть, новые сверху).
Служебные `tts.chunk` по умолчанию скрыты (движок их и не шлёт, пока не включён
`RT_WS_TTS_CHUNKS=1`), чекбокс их показывает. Счётчик «невалидных» — сообщения,
не прошедшие проверку контракта.

### Режим «только мой голос» (микрофон → перевод голосом)

Чтобы переводить **свою** речь и видеть в панели всю цепочку, движок целиком не
нужен:

```bash
python scripts/mic_subtitles.py --from ru --to en --gain 5   # терминал 1
cd ui && npm run dev                                         # терминал 2 → /pipeline
```

Скрипт поднимает тот же WebSocket `ws://localhost:8765` и шлёт те же события,
поэтому UI ничего не знает о разнице. Отличия от `python -m engine.orchestrator`:

- работает только микрофон (поток `out`), WASAPI loopback не открывается, поэтому
  озвучка не может вернуться на вход и программа не переводит сама себя;
- перевод звучит в наушники/колонки (XTTS-v2), а микрофон на это время глушится
  полудуплексом; `--silent` выключает озвучку совсем — тогда XTTS не загружается;
- фраза закрывается паузой 400 мс или принудительно через 4 с речи
  (`--silence-ms`, `--max-phrase-ms`);
- фраза, простоявшая в очереди дольше `--stale-ms` (3 с), показывается текстом,
  но не озвучивается: синтез идёт последовательно, и на непрерывной речи звук
  иначе отстаёт всё сильнее;
- отбрасываются заученные «титры» whisper и залипания вида «No, no, no…» ×100,
  а ответ NLLB, оставшийся на языке оригинала, не уходит в синтез.

Полезные флаги: `--gain` (тихий ноутбучный микрофон: пик ниже 0.05 — whisper
начинает выдумывать слова, скрипт меряет уровень при старте и подсказывает),
`--mic-index` (номера: `python scripts/audio_smoke.py --list`), `--voice`,
`--tts-chunk-size` (меньше — раньше слышен первый звук), `--no-half-duplex`
(можно только в наушниках).

Задержка «конец фразы → первый звук перевода» на RTX 4050: первая фраза ~3 с
(XTTS считает латенты голоса), дальше ~1.5 с.

Привязка данных к фразе: `stt.final` не несёт id реплики, а `metrics.latency` —
ссылки на фразу, поэтому UI опирается на порядок. Движок обрабатывает фразы одного
потока строго по очереди (`engine/orchestrator/pipeline.py`, один воркер на
конвейер): очередной `translation.ready` относится к самой старой непереведённой
реплике, очередная `metrics.latency` — к самой старой переведённой реплике без
метрик. Если движок когда-нибудь начнёт слать `ref_utterance_id` и в `stt.final`,
привязку можно будет упростить (см. «Вопросы к владельцу»).

## ПРЕДЛОЖЕНИЕ: REST-контракт истории для оркестратора

> Это **предложение** Агента E, а не утверждённый контракт. В `ARCHITECTURE.md`
> и `engine/contracts/` REST не описан — там только WebSocket. Прошу владельца
> проекта утвердить (или поправить) формы ниже; тогда их можно будет вынести в
> `engine/contracts/` отдельным PR. Пока контракт не утверждён, UI ходит в
> собственные заглушки `src/app/api/**` поверх `mocks/data.json`.

База: `http://localhost:8766` (порт рядом с WebSocket 8765). Кодировка UTF-8,
все временные метки — `integer`, unix-время в миллисекундах, как `ts` в событиях.
Поля названы ровно как колонки в `db/schema.sql`, чтобы строки отдавались без
переименований.

### `GET /api/sessions`

Список сессий, новые сверху.

```json
{
  "sessions": [
    {
      "id": 3,
      "started_at": 1758240000000,
      "ended_at": 1758240315000,
      "lang_from": "en",
      "lang_to": "ru",
      "audio_path": "recordings/session-3.wav",
      "utterance_count": 5,
      "duration_ms": 315000
    }
  ]
}
```

- `id`, `started_at`, `ended_at`, `lang_from`, `lang_to`, `audio_path` — строка
  таблицы `sessions` как есть (`ended_at` и `audio_path` могут быть `null`);
- `utterance_count` — **производное**, `COUNT(*)` по `utterances` этой сессии;
- `duration_ms` — **производное**, `ended_at - started_at`, `null` для идущей сессии.

Оба производных поля нужны списку истории (ARCHITECTURE.md 4.6: «дата, языки,
длительность, кол-во реплик»). Если движку их считать неудобно — скажите, UI
посчитает `duration_ms` сам, но `utterance_count` без запроса всех реплик не получить.

### `GET /api/sessions/:id`

Сессия и её транскрипт (реплики по возрастанию `t_start_ms`).

```json
{
  "session": { "...": "как в /api/sessions" },
  "utterances": [
    {
      "id": 101,
      "session_id": 3,
      "t_start_ms": 1200,
      "t_end_ms": 4100,
      "speaker": "in",
      "lang": "en",
      "text": "Hi, can you hear me well?",
      "translation": "Привет, хорошо меня слышно?",
      "translation_lang": "ru"
    }
  ]
}
```

Строки `utterances` — 1:1 с таблицей: `speaker` совпадает со `stream`
(`"in" | "out"`), `translation` и `translation_lang` могут быть `null`, пока
перевод не готов. Неизвестный `id` → `404` с телом `{"error": "session not found"}`.

### `GET /api/sessions/:id/audio`

Сырое аудио сессии (`sessions.audio_path`), `Content-Type: audio/wav`.
Желательна поддержка `Range` — плеер перематывает. Если записи нет
(`audio_path IS NULL`) → `404`, UI тогда не рисует `<audio>`.

### `GET /api/voices`

```json
{
  "voices": [
    {
      "id": "v_ab12cd",
      "name": "Мой голос (ru)",
      "lang": "ru",
      "sample_path": "voices/v_ab12cd.wav",
      "created_at": 1757980800000
    }
  ]
}
```

Строки таблицы `voices`; `id` — это `voice_id` из контрактов, он же уходит в
`session.start`. «Голос по умолчанию» отдельной записью не нужен — в UI это
пункт «без клона», который шлёт `voice_id: null` (для kk клон не предусмотрен).

### Заглушки на стороне UI

`src/lib/server/history.ts` сначала пробует сходить в `ENGINE_HTTP`
(таймаут 1.5 с); если движок недоступен — отдаёт `mocks/data.json`. Этой
логикой пользуются и страницы `/history*` (серверный рендер), и route handlers
`src/app/api/**` — форма ответа одна и та же. Аудио в мок-режиме —
синтезированный тон (реальных WAV в репозитории нет, `*.wav` в `.gitignore`).

## Вопросы к владельцу проекта

1. **REST-контракт истории** (раздел выше) — утвердить формы ответов, порт 8766 и
   производные поля `utterance_count` / `duration_ms`.
2. **`ref_utterance_id` не с чем сопоставлять.** `translation.ready` несёт
   `ref_utterance_id` (id строки в `utterances`), но `stt.final` id реплики не
   содержит — у UI нет ключа, по которому он мог бы её найти. Сейчас UI
   привязывает перевод по `src_text`, а при неудаче — к самой старой реплике без
   перевода (порядок FIFO движок гарантирует). Это ломается, если движок
   когда-нибудь начнёт переводить фразы параллельно. Предлагаю добавить
