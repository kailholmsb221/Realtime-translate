# CLAUDE.md — правила работы над проектом Realtime Translator

Ты — один из нескольких агентов, параллельно работающих над этим репозиторием. Перед началом любой задачи прочитай `ARCHITECTURE.md` полностью.

## Законы (нарушать нельзя)

1. **Работай только в своей зоне.** Тебе в промте назначена папка (например `/engine/stt`). Не редактируй файлы вне неё, кроме добавления зависимостей в свой `requirements-<модуль>.txt` (у каждого модуля свой файл; общий `requirements.txt` только подключает их через `-r`).
2. **Контракты неприкосновенны.** Файлы в `/engine/contracts/`, схема БД в `/db` и раздел 5 `ARCHITECTURE.md` менять запрещено. Если контракт мешает или в нём ошибка — остановись и напиши владельцу проекта, предложи изменение текстом, не кодом.
3. **Никаких платных API и сервисов.** Только бесплатные open-source модели, перечисленные в `ARCHITECTURE.md`. Не добавляй ключи, подписки, облачные вызовы.
4. **Уважай бюджет VRAM (6 GB).** Не повышай размер моделей (whisper только `small` int8), не загружай модели, не указанные в разделе 6 `ARCHITECTURE.md`.
5. **Не выполняй деструктивных команд** (удаление вне своей папки, force-push, изменение системных настроек Windows). Установку системных программ (VB-Cable, драйверы) не делай — напиши инструкцию пользователю.
6. **Определение "готово":** задача завершена, только когда (а) код написан, (б) есть автотесты, (в) `pytest` / `npm test` зелёные, (г) обновлён README своей папки с инструкцией запуска. Без тестов работу не сдавай.
7. **Один агент — одна ветка.** Работай в своей ветке `feat/<имя-модуля>`, коммиты маленькие, сообщения на английском в формате `stt: add silero vad segmentation`.
8. **Не переписывай чужой код "заодно".** Заметил проблему в чужом модуле — оставь комментарий `TODO` и сообщи в итоговом отчёте, не чини сам.
9. **Секретов в репо нет.** Никаких токенов, паролей, личных данных в коде и коммитах.
10. **Сомневаешься — спроси.** Если требования противоречат друг другу или `ARCHITECTURE.md`, остановись и задай вопрос, а не выбирай молча.

## Технический стандарт

- Python 3.11, asyncio; форматирование `ruff format`, линт `ruff check`; типизация обязательна (mypy-friendly).
- Все взаимодействия между модулями — через события из `/engine/contracts/` или интерфейсы, описанные в `ARCHITECTURE.md`. Прямые импорты внутренностей чужого модуля запрещены. Общие типы событий берутся из `engine/contracts/events.py` (генерируется на этапе 0, менять нельзя).
- Тяжёлые модели (whisper, NLLB, XTTS, KazakhTTS2) загружаются лениво и только через фабрики; в юнит-тестах используются фейковые реализации того же интерфейса. Тесты с реальными моделями помечаются `@pytest.mark.real_models` и пропускаются, если не задана переменная окружения `RT_REAL_MODELS=1`.
- UI: Next.js + TypeScript strict, состояние без сторонних стейт-менеджеров (достаточно React), стили Tailwind.
- Аудио внутри движка: PCM 16 kHz mono int16, если контракт не говорит иначе. TTS отдаёт PCM 24 kHz mono int16, ресемплинг делает orchestrator/audio_io.
- Тесты кладутся рядом: `/engine/tests/test_<модуль>.py`. Для аудио-модулей — тесты на WAV-фикстурах из `/engine/tests/fixtures/` (создай короткие сэмплы сам через тон-генератор).
- Логирование: стандартный `logging`, уровень настраивается env-переменной `LOG_LEVEL`.

## Как запускать проект

- Движок: `python -m engine.orchestrator` (пока модуля нет — smoke-скрипты в `/scripts`).
- UI: `cd ui && npm run dev`.
- Тесты: `pytest engine/tests`, `cd ui && npm test`.
